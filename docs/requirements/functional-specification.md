## 01 범위와 통합 기준

표기: 필수 = 1차 출시 기준 / 권장 = 1차 여유 시 구현 / 후속 = 2차 이후 / 제외 = 이번 개발 범위 밖

| 영역 | 통합 범위 |
| --- | --- |
| 1차 필수 | 회원·인증, 모의계좌·초기화, 시장가·지정가 주문, 미체결·체결, 잔고·손익, 종목조회, 기본 차트·관심목록,<br>랭킹, 공시·재무 수집, RAG, 근거 기반 AI 질의 |
| 1차 권장 | 최우선 호가주문, WebSocket 시세, 분봉, 종목메모, 규칙형 전략·신호·알림, 가상화폐 확장 |
| 후속 | 자산·랭킹 이력, 기업 비교·추세, 개인 포트폴리오 AI 분석, 투자내역 질의, 공시 자동 동기화·알림, 관리<br>자 화면, 이상 거래 감지 |
| 제외 / 장기 | 해외 주식 실시간 연동, 차트게임, 8분할 멀티차트·4종목 비교차트, 무제한 지표, AI 가격예측·AI 매매신<br>호 |

### 원문이 다른 부분의 통합 선택안

| 쟁점 | 본 문서의 통합 기준 |
| --- | --- |
| AI 범위 | A의 제외 항목인 가격예측·AI 매매신호는 유지한다. B의 공시·재무 기반 설명형 AI는 별개 기능으로 1<br>차 필수에 포함한다. |
| 초기자금 | 회원가입 시 지급(B)을 계좌 개설 시 지급(A)으로 통일한다. 계좌당 1,000만원 고정안을 적용하며 사용<br>자 지정 금액은 보류한다. |
| 체결 시점 | 현재가 즉시 처리(B) 대신 A의 1분 배치를 적용한다. 주문 접수 결과와 실제 체결 결과를 구분한다. |
| 차트·관심종목 | A 필수 / B 2차 → 기본 기능은 필수, 고급 차트는 후속으로 정리한다. |
| 랭킹·재무 | A 권장 / B MVP → AI 통합 서비스의 필수로 배치한다. |
| 호가주문 | A 필수이나 데이터 의존성이 있어 권장으로 조정한다. 최우선 1호가 확보·이용조건 확인이 선행되어야<br>한다. |
| 랭킹 단위 | 사용자 단위(B) 대신 계좌 단위(A)를 적용하고 닉네임을 표시한다. 계좌는 시장별로 구분하는 설계안을<br>사용한다. |

위 우선순위는 두 문서를 합치기 위한 제안이다. 모의매매와 AI를 모두 포함해 기존 단일 문서보다 범위가 커졌으므로 일정은 14절의 의 존성과 보류 항목을 기준으로 확정한다.

## 02 회원·인증·내 정보

출처: A §2, §14 / B AUTH-01\~04, USER-01. 기존 B의 기능 ID는 유지하고 추가 기능에 새 ID를 부여했다.

### AUTH-01 · 회원가입 | 필수

이메일·비밀번호·비밀번호 확인·닉네임으로 계정을 생성한다. 비밀번호는 해시로 저장한다. 가입 직후 미인증 상태이며 자금은 계좌 개설 시 지급한다.

**입력 → 출력** 가입 정보 → 회원 ID, 가입 결과

**예외·검증** 이메일·닉네임 중복, 형식 오류, 비밀번호 불일치, 필수값 누락

### AUTH-05 · 이메일 인증 | 필수

인증 링크로 계정을 활성화한다. 토큰 유효기간은 24시간, 재발송은 1분당 1회로 제한한다.

**입력 → 출력** 인증 토큰 또는 재발송 요청 → 인증 상태

**예외·검증** 만료·잘못된 토큰, 재발송 제한. 미인증 로그인에는 인증 안내와 재발송 경로 제공

### AUTH-06 · 구글 OAuth 로그인 | 필수

최초 구글 로그인 시 회원을 생성한다. 같은 이메일의 기존 계정과 연결해 중복 생성을 방지한다. 인증된 구글 이메일 은 별도 메일 인증을 생략한다.

**입력 → 출력** 구글 인증 결과 → 회원 정보, 서비스 토큰

**예외·검증** 구글 인증 실패. 계정 연결은 검증된 이메일과 계정 소유 확인을 전제로 한다(보완 제안).

### AUTH-02 · 로그인 | 필수

이메일 또는 구글 인증 후 동일 형식의 JWT를 발급한다. 액세스 토큰 1시간, 리프레시 토큰 14일. 비밀번호 5회 연속 실패 시 10분 제한.

**입력 → 출력** 이메일·비밀번호 또는 OAuth 결과 → 토큰, 사용자 기본정보

**예외·검증** 인증 실패, 미인증 계정, 로그인 제한 상태

### AUTH-03 / 04 · 토큰 재발급·로그아웃 | 필수

유효한 리프레시 토큰으로 액세스 토큰을 갱신한다. 로그아웃 시 해당 리프레시 토큰을 무효화한다.

**입력 → 출력** 리프레시 토큰 / 인증 사용자 → 새 토큰 / 로그아웃 결과

**예외·검증** 만료·위조·무효화 토큰은 재로그인 요구. 미인증 요청 거부

### USER-01 · 내 정보 조회 | 필수

이메일·닉네임과 계좌별 현금·총자산·수익률·내 순위를 제공한다. 다계좌의 수익률을 단순 합산하지 않는다(통합 보완).

**입력 → 출력** 인증 사용자, 선택 계좌 → 사용자·계좌 요약

**예외·검증** 회원 없음, 타인 계좌 접근, 랭킹 미생성

## 03 모의계좌와 자금 초기화

출처: A §3\~4 / B BR-01. 계좌 개설·초기화의 금액을 동일하게 맞추었다.

### ACCOUNT-01 · 계좌 개설 | 필수

사용자당 활성 계좌 최대 3개. 초기자금 10,000,000원, 투자기간 제한 없음. 시장 구분(국내 주식/가상화폐)을 계좌 속 성으로 두는 방식을 제안한다.

**입력 → 출력** 계좌명, 시장 → 계좌 ID, 현금잔고

**예외·검증** 4번째 활성 계좌 개설 차단. 가상화폐 미출시 시 해당 시장 계좌 개설 비활성화

### ACCOUNT-02 · 계좌 목록·상세 | 필수

목록은 계좌명·평가금액·총손익률, 상세는 현금·보유종목·평가손익·누적 실현손익을 제공한다.

**입력 → 출력** 인증 사용자, 계좌 ID → 계좌 목록 또는 상세

**예외·검증** 없는 계좌, 타인 계좌(403), 평가시세 누락

### ACCOUNT-03 · 계좌 해지 | 필수

보유종목이 없는 계좌만 해지한다. 과거 주문·체결 이력은 조회용으로 보존한다. 미체결 주문이 있으면 먼저 취소하도 록 한다(보완 제안).

**입력 → 출력** 계좌 ID → 해지 결과

**예외·검증** 보유종목 존재 시 전량 매도 안내. 미체결 잔존, 권한 없음

### RESET-01 · 자금 초기화 | 필수

계좌 상세의 버튼으로 보유종목을 매도 체결 없이 전량 제거하고 현금을 1,000만원으로 설정한다. 평가·실현손익 표시 를 0으로 바꾸고 수익률 기준 시점을 갱신한다.

**입력 → 출력** 본인 계좌, 초기화 확인 → 새 현금·손익·기준시각

**예외·검증** 당일 재실행 409, 타인 계좌 403. 실패 시 전체 롤백

### 초기화 공통 규칙

- 계좌당 KST 자정 기준 하루 1회. 계좌 3개를 보유하면 하루 최대 3회 가능하다.

- 주문·체결 이력은 삭제하지 않는다. 과거 손익은 조회용으로 보존하고 현재 성과 계산에서는 이전 구간을 제외한다.

- 쿠폰 발급·보유·만료 기능은 사용하지 않는다.

### 거래 정합성을 위한 보완 제안

초기화 전 경고와 확인 화면을 제공한다. 초기화 트랜잭션 안에서 미체결 주문 취소, 예약 현금·수량 해제, 포지션 제거, 현금 재설정, 성과 구간 갱신을 함께 처리한다. 동일 계좌의 체결 배치와 초기화를 직렬화하고 요청 중복으로 초기화 가 반복되지 않게 한다.

## 04 주문·체결

출처: A §5 / B TRADE-01\~03, BR-02\~04·06. 실제 금융거래 없이 서비스 내부 가상자산만 사용한다.

### TRADE-01 / 02 · 모의 매수·매도 | 필수

시장가 또는 지정가 주문을 접수한다. 매수는 수량×가격+수수료가 가용현금을 초과하면 차단하고, 매도는 가용 보유 수량을 초과하면 차단한다.

**입력 → 출력** 계좌, 종목, 매수/매도, 주문유형, 수량, 지정가 → 주문 ID·접수 상태

**예외·검증** 잔액·수량 부족, 0 이하 수량, 종목·시세 오류, 거래정지, 잘못된 호가단위

### TRADE-04 · 1분 배치 체결 | 필수

시장가는 다음 배치의 최신가로 체결한다. 지정가 매수는 최신가≤지정가, 매도는 최신가≥지정가일 때 해당 최신가로 체결한다. 현금·보유수량·손익·이력을 원자적으로 갱신한다.

**입력 → 출력** 미체결 주문, 최신 유효 시세 → 체결 또는 대기 상태

**예외·검증** 체결 직전 잔액·수량 재검증. 유효 가격 없음 시 체결 보류와 사유 표시(보완 제안)

### TRADE-05 · 미체결 조회·취소 | 필수

계좌별 미체결 주문을 조회·취소한다. 국내 주식 지정가는 당일유효를 기본으로 장 마감 시 자동 취소한다.

**입력 → 출력** 계좌 ID, 주문 ID → 미체결 목록 또는 취소 결과

**예외·검증** 이미 체결·취소된 주문, 타인 주문, 체결과 취소의 동시 실행

### TRADE-03 · 주문·체결 내역 | 필수

## 06 포트폴리오·손익·랭킹

출처: A §6·13 / B PORT-01\~03, RANK-01\~03, BR-05. 모든 계산은 선택 계좌와 성과 구간을 기준으로 한다.

### PORT-02 · 총자산·수익률 | 필수

현금과 보유종목 평가금액을 합산한다. 초기화 이후에는 새 기준자산과 시점으로 수익률을 계산한다.

**입력 → 출력** 계좌, 유효 시세 → 현금·평가액·총자산·손익·수익률

| 항목 | 계산 기준 |
| --- | --- |
| 평가금액 / 총자산 | 현재가 × 수량 / 현금 + 보유종목 평가금액 합계 |
| 평가손익 | (현재가 - 평균매입가) × 보유수량 |
| 실현손익 | (매도가 - 평균매입가) × 매도수량 - 수수료. 매도 체결 시 누적 확정 |
| 총수익률 | (현재 총자산 - 성과구간 기준자산) ÷ 성과구간 기준자산 × 100 |
| 성과구간 기준 | 계좌 개설 또는 가장 최근 초기화 시점부터 계산. 기준자산은 통합안 1,000만원 |

매수 수수료 처리의 구체화 제안은 16절 P-03을 따른다. 팀 확정은 14절 합의 목록으로 관리한다. 손익과 현금 변동이 일치하도록 중복 차 감하지 않아야 한다.

### RANK-01 / 02 · 수익률 랭킹·내 순위 | 필수

**입력 → 출력** 계좌별 성과, 노출 설정 → 순위·닉네임·총자산·수익률

**예외·검증** 평가 누락, 랭킹 미생성. 옵트아웃 계좌 제외. 동률 기준과 초기화 후 참여 기준은 별도 확정

## 08 RAG 검색 파이프라인

### RAG-02 · 청크 생성 | 필수

긴 문서를 검색 가능한 조각(청크)으로 분할하고 기업·연도·문서유형 메타데이터를 부여한다. 문서와 위치를 역추적할 수 있어야 한다.

**입력 → 출력** 정제 문서 → 청크 목록·문서 연결 정보

**예외·검증** 빈 문서·비정상 길이. 청크 크기·겹침 기준은 표본 평가 후 확정

### RAG-03 · 임베딩 생성 | 필수

각 청크를 의미 검색용 숫자 벡터로 변환한다. 모델과 버전 정보를 저장하는 방식을 제안한다.

**입력 → 출력** 청크 → 임베딩 벡터

**예외·검증** 모델/API 실패, 호출 제한. 실패 청크를 식별하고 재시도

### RAG-04 · Vector DB 저장 | 필수

벡터와 메타데이터를 저장하고 문서·청크 ID로 원문을 연결한다.

**입력 → 출력** 벡터, 메타데이터 → 저장 결과

**예외·검증** DB 연결·저장 실패. 모델 변경 시 인덱스 혼용 방지(보완)

### RAG-06 · 메타데이터 필터 | 필수

질문에서 기업·기간·공시유형을 파악해 검색 범위를 제한한다.

**입력 → 출력** 구조화된 질문 조건 → 검색 필터

**예외·검증** 기업명·기간 인식 실패 시 추가 확인. 다른 기업이나 기간을 임의 선택하지 않는다.

### RAG-05 · 유사 문서 검색 | 필수

질문과 관련된 상위 K개 청크를 검색하고 유사도·출처를 반환한다. 답변에 사용할 수 있는 근거인지 확인한다.

**입력 → 출력** 질문, 검색 필터 → 청크·유사도·출처

**예외·검증** 검색 결과 부족·무관한 근거는 근거 부족 상태로 반환. K와 적합성 기준은 검증 후 확정

### **처리** 순서와 재처리 원칙

공시 수집 → 전처리 → 청크 생성 → 임베딩 → Vector DB 저장 사용자 질문 → 메타데이터 필터 → 유사 문서 검색 → 근거 기반 답변

### AI-03 · Tool Routing | 필수

질문에 따라 주가·정형 재무·재무 계산·공시 검색 도구를 선택하고 필요 시 복수 결과를 결합한다. 개인 자산·거래 도구 는 후속 단계에서 연결한다.

**입력 → 출력** 분석된 질문 → 도구 실행계획·조회 결과

### AI-04 · 재무정보 조회 | 필수

정량적 질문은 정형 재무 데이터를 우선 조회해 수치·단위·기간·설명을 제공한다.

**입력 → 출력** 기업, 연도/기간, 재무항목 → 재무 수치와 설명

**예외·검증** 데이터 없음, 단위·회계기준 불명확

### AI-05 · 재무지표 계산 | 필수

영업이익률·부채비율·ROA·ROE 등을 계산 도구로 산출한다. 공식과 사용 기간을 답변에서 확인할 수 있게 한다.

**입력 → 출력** 필요 재무값 → 지표값·계산 근거

**예외·검증** 분모 0, 필수 데이터 누락. ROA·ROE 분모의 평균/기말 기준은 별도 확정

### AI-06 · 공시 RAG 분석 | 필수

질적 질문에 대해 관련 공시 청크를 검색하고 LLM이 근거 기반 설명을 생성한다.

**입력 → 출력** 질문, 검색 조건 → 답변·근거 청크·출처

**예외·검증** 관련 근거 부족, 기업·기간 불일치

### AI-09 / 10 · 출처·근거 부족 처리 | 필수

답변에 사용한 공시·재무 출처명, 공시일, 문서 식별정보를 제공한다. 근거가 부족하면 추측하지 않고 확인 불가를 반환 한다.

**입력 → 출력** 도구/RAG 결과 → 출처 포함 답변 또는 부족 안내

**예외·검증** 출처 없는 수치·설명을 확정적으로 제시하지 않는다. 근거가 있는 부분만 구분해 답변

### AI 동작 경계 · 통합 보완 제안

AI는 조회·검색·계산만 수행하며 주문·초기화·계좌 변경을 실행하지 않는다. 공시 본문은 분석 데이터로만 취급하고 문서 안의 지시문으로 시스템 동작을 바꾸지 않는다. 개인 데이터 도구는 서버에서 본인 계좌 권한을 확인한다.

| 손익·랭킹 | 수동 계산과 총자산·손익·수익률 일치. 초기화 이전 성과 제외. 00:10 갱신과 상위 100·내 순위 제공, 옵<br>트아웃 제외 |
| 수집·검색 | 표본 공시의 원문·정제문·청크·검색 결과를 연결해 추적 가능. 기업·기간 필터가 다른 기업 자료를 섞지<br>않음 |
| AI 답변 | 재무 질문은 실제 저장값·단위·기간과 일치. 공시 질문은 확인 가능한 출처 제공. 근거 부족·분모 0·도구<br>장애에서 수치나 근거를 만들어내지 않음 |
| 운영 | 배치 실패 재시도·알림 확인. 300봉 성능 목표 측정. 비밀번호·토큰 로그 노출 없음 |

### 검증용 재무·시세 데이터

기업·기간별 정답이 있는 소규모 표본으로 AI 수치·출처·검색 적합성을 먼저 점검한다. 가격 누락, API 장애, 정정공시, 초기화 직전 미체결 주문 등 정상·실패 사례를 함께 사용한다.

## 14 개발 순서·합의 필요사항

일정과 역할은 3인·3개월을 위한 통합 제안이며 확정된 납기나 역할 배정이 아니다.

| 시기 | 개발 순서와 완료 목표 |
| --- | --- |
| 1개월차 | 인증·계좌·종목·1분 체결·잔고 기반 구축. 병행하여 공시/재무 공급자와 표본 수집, 정규화·청크·검색 가능성<br>검증 |
| 2개월차 | 초기화·미체결·손익·기본 차트·관심목록·랭킹 완성. RAG·재무 조회/계산·Agent Routing 연결. WebSocket은<br>권장 범위로 진행 |
| 3개월차 | 모의매매와 AI 화면 통합, 출처·근거 부족 처리, 장애·정합성·성능 검증. 필수 완료 후 호가·가상화폐·전략/신<br>호 검토 |

### 역할 분담 제안

팀원 A: 인증·계좌·초기화·랭킹 및 공통 화면 팀원 B: 종목·주문/체결·잔고·차트·시세 및 거래 화면 팀원 C: 공시·재무·RAG·AI Agent 및 AI 화면 통합 테스트·배포·데이터 규칙은 공동 담당. 프론트엔드 작업을 각 기능 담당에 포함한다.

## 16 ERD·API 연결 기준

v1.1 추가. 프로젝트 이름을 인베스트랩(InvestLab)으로 정의하고 ERD·API 설계 문서와 연결한다.

서비스 소개 문구: 공시·재무 분석 AI와 함께하는 모의투자 플랫폼. 제품의 핵심 흐름은 기업분석 → 모의매매 → 성과 확인이다.

| 정책 ID | ERD·API v1.0에서 채택한 설계 제안 |
| --- | --- |
| P-01 계좌·초기자금 | 활성 계좌는 사용자당 3개, 시장별 계좌를 사용한다. 계좌 개설 시 1,000만원 지급. 닉네임은 중복 불가,<br>기본계좌 자동생성은 하지 않는다. |

| P-03 비용·가격 | 수수료율·세금·호가단위·최소금액·가격 유효시간은 시장 설정값이다. 미설정 시장의 주문은 거부한다.<br>매수 수수료는 취득원가에 포함하고 매도 수수료·세금은 실현손익에서 차감한다. 문서 계산 예시만 비<br>용 0원을 사용한다. |

| P-05 초기화 | 미체결 주문 취소·예약 해제·포지션 제거·현금 재설정·성과구간 교체를 원자적으로 실행한다. 과거 성과<br>구간·현금원장·체결은 보존한다. |

### 문서 간 적용 순서

기능 범위·우선순위는 기능명세서를 따른다. 위 P-01\~08은 미정 항목을 구체화한 설계 제안이며 팀의 승인 완료를 의 미하지 않는다. 구현 작업을 시작하기 전 정책값을 확정하고 세 문서를 함께 갱신한다. API·ERD에서 필수/권장/후속 범 위를 유지한다.
