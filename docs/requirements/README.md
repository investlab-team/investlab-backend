## 수정 방법

1. 이슈에 바꿀 정책·기능 ID·관련 API 또는 테이블을 적는다.
2. 위 Markdown의 해당 절을 수정하고, 영향을 받는 다른 명세와 구현된 OpenAPI 계약도 함께 확인한다.
3. 미확정 항목을 확정할 때는 이슈·Discussion 등 결정 근거를 남긴다. 단순 구현 결과를 문서상 요구사항으로 자동 승격하지 않는다.
4. PR에서 변경 전후 정책과 호환성을 검토한다. 과거 PDF를 별도로 최신화할 필요는 없다.

각 문서 목차는 원본 페이지별 절로 연결된다. `source-page-N` 앵커와 원본 페이지 주석은 초기 전환 대조를 위한 위치 정보다. 긴 표의 셀 안 줄바꿈은 원본의 줄바꿈을 보존한 것이다. DB 관계도 7장은 관계선·복합 FK 주석 손실을 막기 위해 이미지로 보존했고, 38개 테이블 정의와 관계·제약·규칙 본문은 Markdown으로 편집할 수 있다. 관계도 이미지 재작성은 별도 작업이다.

## 문서 간 차이와 적용 원칙

이 문서들은 같은 날짜·버전의 계약이 아니다. 기능명세는 2026-09-15 통합안, API는 v1.0, DB는 2026-10-10 결정 반영 v1.1이다. DB가 참조하는 API v1.3 원본은 저장소에 없다. 전환 과정에서 없는 API를 추정해 만들거나 아래 충돌을 조용히 덮어쓰지 않았다.

| 항목 | 기능/API의 이전 내용 | DB v1.1 내용·확인할 점 |
| --- | --- | --- |
| API 경로 | `/me`, `/instruments/*`, `/me/watch-items` 등 v1.0 경로 | 대응표에는 `/users/me/*`, `/stocks/*`, `/watchlist-items` 등 v1.3 경로. 새 API 계약 확정 전 혼용하지 않는다. |
| 랭킹 동률 정렬 | 수익률 공동순위, 같은 순위에서는 계좌 ID 순 | 같은 순위에서는 총자산 큰 순. 변경 결정과 API 응답 기준을 함께 대조한다. |
| 랭킹 참여 | 별도 대기기간 미적용 제안 | 개설·초기화 당일 제외, 현재 구간 체결 필요. 조회 시 숨김 후 재순위 계산. |
| 관심목록 삭제 | 목록 소속만 삭제하고 관심종목 유지 제안 | 다른 목록에 없는 관심종목은 함께 삭제. |
| 회원 상태·탈퇴 | 기존 가입·로그인 중심, 탈퇴·닉네임 온보딩 API 상세 부족 | PENDING_NICKNAME과 7일 탈퇴 유예·재로그인 취소·재가입 충돌 규칙 추가. |
| 멱등 오류 코드 | API v1.0: IDEMPOTENCY_CONFLICT | DB 규칙: IDEMPOTENCY_KEY_CONFLICT. 공개 오류 코드는 API 계약 갱신 시 확정한다. |
| AI 대화·고지 | API v1.0의 답변 모델 기준 | 대화 테이블·conversation_id·disclaimer_version 추가. 요청·응답 계약 동기화 필요. |

기능 범위는 기능명세, 필드·관계·제약은 DB 설계, 요청·응답은 API 명세를 참조하되 충돌이 있으면 해당 결정 근거와 담당자의 합의로 해결한다. 원문의 미확정 항목과 과거 개발 일정·역할 제안은 현재 합의로 단정하지 않는다. 현재 담당 배정은 API 담당자 표, 기술·저장소·배포 규칙은 아키텍처·협업 규약을 따른다. 현재 DB 선택은 PostgreSQL 16이며, 과거 문서의 Redis·벡터 저장소 언급은 도입 완료를 의미하지 않는다.
